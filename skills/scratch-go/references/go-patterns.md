# Go 工程模式

本文件只定义项目实现约定。命令与验收流程见 [SKILL.md](../SKILL.md)；[错误](error.md)、[日志](logging.md)、[API](api-spec.md)及[数据库](database-spec.md)规则分别由对应专题维护。

## 1. 项目结构

- 可执行入口放在 `cmd/<command>/`，内部实现放在 `internal/`；服务按服务名命名，Worker/CLI 按职责命名。
- 按业务职责组织包，不强制固定分层；业务代码不依赖 `*gin.Context` 或数据库驱动类型。
- 入口显式构造并注入依赖，不使用可变全局状态或万能 `common/utils/base` 包。默认使用具体类型，需要替换行为时在使用方定义最小接口。
- 人工编写的源码注释使用英文，不设函数行数门槛。
- Go 版本约束只维护在 `go.mod`，遵循 `GOTOOLCHAIN`；依赖固定具体版本，不使用 `@latest`。

## 2. 配置与外部依赖

### 2.1 默认配置与环境变量

只维护一份入库的 `configs/config.yaml`，开发、测试、生产共用，各环境仅通过环境变量覆盖。默认值只在 YAML 中定义；进程从项目根目录读取固定路径，不搜索其他位置或回退到代码默认值。

`internal/config` 统一执行“读取 YAML → 环境变量覆盖 → 校验”，入口调用一次后组装依赖。业务代码不自行读取环境变量，不使用全局配置或热更新。

| YAML 字段 | 环境变量 | 默认值 |
| --- | --- | --- |
| `http.addr` | `HTTP_ADDR` | `:8080` |
| `shutdown.timeout` | `SHUTDOWN_TIMEOUT` | `10s` |
| `log.level` | `LOG_LEVEL` | `info` |

Worker/CLI 只保留适用项。环境变量采用大写下划线命名，每个可覆盖字段显式映射，README 记录名称、默认值和约束。

- YAML 拒绝未知字段、重复键、类型错误及多份文档。
- 环境变量未设置时保留 YAML 值；显式空值、`0`、`false` 均参与覆盖，再按字段约束校验。只读取声明支持的变量。
- 时长采用 Go duration 格式；关闭期限大于零，日志级别限定 `debug/info/warn/error`。
- 文件缺失、解析或校验失败时，在监听和依赖构造前以非零状态退出；诊断指出字段、环境变量名称及来源。
- 密码、令牌等通过环境变量注入，不保存真实默认值；相关依赖启用时校验必填。

### 2.2 开发环境

应用不加载 `.env`。`make dev` 构建后通过 POSIX shell 的 `.` 加载根目录 `.env` 并导出变量；文件不存在时使用继承环境，加载失败时不启动。文件中的赋值覆盖继承环境，未赋值项保留原值。`make run` 不读取 `.env`。

`.env` 使用 shell 赋值语法，特殊字符用单引号保护，不写命令或命令替换；不用于设置 `SERVICE`、`VERSION` 或构建工具参数。示例维护在 `.env.example`，实际 `.env` 加入 `.gitignore`。

### 2.3 外部依赖

依赖配置放在 `dependencies.<name>`，只为实际使用的依赖增加配置和适配代码；由入口构造并注入可复用客户端。引入时明确连接失败是否阻止启动，以及运行时允许的降级行为。

默认不增加应用层自动重试。启用时明确错误范围、次数、退避与幂等前提，并检查 SDK 重试以避免叠加；重试及退避受调用方上下文控制。写入超时且结果未知时，先通过幂等机制或结果查询处理，不直接重复写入。

## 3. HTTP 服务

### 3.1 路由与适配

- 使用 `gin.New()`，生产使用 release 模式，关闭调试输出；不暴露故障、panic 或延时调试接口。
- 路径不存在返回统一 404；路径存在但请求方法不支持时返回统一 405，并携带 `Allow` 头。
- `internal/httpapi/error_handler.go` 提供统一错误出口，业务映射放在所属 HTTP 适配代码中，遵守 [错误处理](error.md#4-对外错误映射)和 [API 规范](api-spec.md)。出口保存失败结果，不记录日志。
- 复用 Gin 的 `go-playground/validator/v10`，常规校验使用 `binding` 标签，组合规则使用结构级或显式校验；自定义规则和字段名映射在启动时注册。
- 使用 `ShouldBind*`，不使用会提前提交响应的 `Bind*`/`MustBind*`；JSON 沿用解码器默认行为，绑定已执行的校验不重复调用。校验器配置或调用错误按内部故障处理。
- HTTP 层负责解码和不依赖外部状态的参数校验；数据状态、权限归属及业务不变量由业务模块负责。

### 3.2 请求处理与完成边界

请求 ID 接受 1–128 位 `[A-Za-z0-9._-]`；缺失或非法时，用 `crypto/rand.Read` 生成 16 字节并编码为 32 位十六进制。

在 Gin `ServeHTTP` 外层统一处理请求 ID、响应状态跟踪、panic 恢复、日志和指标；Gin 内不再安装同责中间件。请求 ID 和结果状态放入标准上下文，Gin 适配层在上下文回收前保存路由模板与客户端地址；外层不持有 `*gin.Context`，响应记录器保留流式与连接控制能力。

| 结果 | 处理 |
| --- | --- |
| 原始请求被客户端取消，且当前错误由该取消引起 | 保存取消结果，通过 `panic(http.ErrAbortHandler)` 中断，不补写响应 |
| 原始请求仍有效时的内部取消、超时、依赖故障或未知失败 | 响应未提交且可写时返回 `500 / INTERNAL_ERROR`，否则中断 |
| 普通 panic | 保存 panic 值与 `debug.Stack()`；未提交时返回统一 500，已提交时中断，不追加 JSON |
| 业务拒绝、404/405 | 按 API 契约返回 |

客户端取消依据传输层原始请求上下文判定，不能只看派生上下文或 `context.Canceled`；同时发生的独立故障仍保留。恢复层原样抛出 `http.ErrAbortHandler`，不作为新 panic 记录。

普通 HTTP 在 Gin 完成提交、处理链退出并确定最终结果后，统一记录一次完成日志和指标；耗时从请求进入开始，日志级别不影响指标。响应提交后失败保留实际状态，由失败结果决定日志级别及指标 outcome。

实际使用连接接管时，握手完成即结束 HTTP 计时和统计。后续错误、panic、连接清理及关闭日志归协议适配层，不再写 HTTP 响应、不改握手结果，也不依赖 `http.ErrAbortHandler` 关闭连接。

### 3.3 服务生命周期

使用 `http.Server` 承载包装后的 Gin Handler，不使用 `router.Run()`。采用 `main → run → error`：`run` 负责运行与清理，`main` 记录最终失败并设置退出码；监听失败立即返回，`http.ErrServerClosed` 视为正常退出。

SIGINT/SIGTERM 触发关闭时，创建独立于信号上下文的关闭上下文。HTTP 排空、后台任务退出和资源清理共用 `shutdown.timeout` 总时限，各阶段不得重新计时。排空后关闭依赖；期限耗尽则强制关闭，停止等待并以失败退出。

接管连接由协议适配层停止接收、通知关闭及强制回收，与 HTTP 排空并行，共用总时限。

### 3.4 运行指标

使用固定版本的 `github.com/prometheus/client_golang`，独立构造并注入 Registry，注册 Go 运行时和进程采集器。

| 指标 | 类型 | 记录时机 |
| --- | --- | --- |
| `http_server_requests_total` | Counter | 第 3.2 节的完成边界计数一次 |
| `http_server_request_duration_seconds` | Histogram | 同一完成边界记录一次耗时，单位秒 |
| `http_server_requests_in_flight` | Gauge | 请求进入递增，完成边界递减 |

请求计数和耗时使用以下标签；在途 Gauge 不使用结果标签。

| 标签 | 取值 |
| --- | --- |
| `route` | 路由模板；未匹配为 `unmatched` |
| `method` | 固定请求方法集合；未知方法为 `OTHER` |
| `status` | 实际提交状态；未提交为 `none` |
| `outcome` | `success/rejected/failure/timeout/canceled`，按第 3.2 节确定 |

标签不使用动态业务 ID、完整 URL 或错误文本。Histogram 桶在构造时固定，各实例保持一致，README 记录指标、单位、标签和桶配置。内部失败率按 outcome 计算，业务拒绝与客户端取消单独统计。

`GET /metrics` 使用 promhttp 输出标准格式，不套业务 JSON，不计入应用 HTTP 指标；其他应用路由默认纳入统计。运维文档记录不可访问、错误率和延迟告警的窗口、阈值、通知去向及排查步骤；比例告警设置最小请求量，采集可用不等同业务可用。

## 4. 专项验证

- HTTP 测试使用实际路由、中间件和错误出口；本地服务测试纳入普通测试集，不依赖外部运行实例。
- 客户端取消及响应提交后失败，使用真实本地 HTTP 连接验证中断，不仅用 `ResponseRecorder` 判断。
- 验证无正文响应、panic、取消和连接接管的完成边界；每次 HTTP 计数和耗时只记录一次，在途计数归零，接管后的故障不改变握手结果。
- 验证动态路径不增加指标标签基数、`/metrics` 不计入业务指标，以及关闭总时限不会因等待后台任务或接管连接被延长。
